# Changelog

All user-visible changes to Kladde.

## [Unreleased]

- New: Plugins can show their data in Kladde's own table (`host.ui.Table`): the look of note tables with sorting, filter and row count, read-only or editable cell by cell, with optional "+ row" and delete buttons; the plugin decides which columns can be edited and saves the changes itself. The example plugin's page shows its entries in such a table with an "Edit" switch, and a ```` ```logbook ```` block with `edit: yes` edits them right in the note.

### Plugin API

- 1.2.0: `ui.Table` (`PluginTableProps`, `PluginTableColumn`, `PluginTableValue`) and the Markdown helpers `parseMarkdownTable`/`formatMarkdownTable` (`MarkdownTable`). Additions only: plugins written for 1.0 and 1.1 keep working.

## [2.28.0] – 2026-11-27

- New: Build-time plugins ([docs/PLUGINS.md](docs/PLUGINS.md)): own apps built into the Kladde image with their own navigation entries, pages under `/p/<id>`, command palette entries, a card with settings under Settings → Features (switched per user), routes under `/api/p/<id>`, background jobs, note events, files in the account export and their own database tables. Plugins talk to Kladde only through the new package `@kladde/plugin-api`, which has its own SemVer version (1.0.0), so Kladde releases do not break them. `kladde.plugins.json` pins the plugin packages; `npm run plugins` (also in the Docker build) installs them and stops the build when a plugin's plugin API, React or Kladde range does not fit, a pinned version is not the installed one or two plugins share an id. Plugin tables (`p_<id>_…`) are created by numbered migrations that run at start after a backup; SQLite's authorizer keeps them away from Kladde's tables, a changed released step or a downgrade stops the start, and `cli plugins purge <id>` removes the data of a plugin that was taken out. An example plugin (`examples/kladde-plugin-logbook`) and a template for an ops repository that builds the image with plugins (`docs/ops-repo-template/`) are included.
- New: Plugins can draw their own blocks in notes (```` ```<id> ```` fenced blocks, offered in the `/` menu; without the plugin they stay plain code), add tools for AI assistants on the MCP endpoint (`<id>_<name>`, only for users who switched the plugin on, writing tools only for connections that may write) and send notifications to the bell and as Web Push. The example plugin shows all three: a ```` ```logbook ```` block with the latest entries, the tools `logbook_list_entries` and `logbook_add_entry`, and a notification when an assistant wrote an entry.
- New: `APP_TITLE` gives the app its own name instead of "Kladde": browser tab, installed app (manifest), sign-in page, top bar and passkey prompts.
- New: `LOGIN_METHODS` chooses the sign-in methods a server offers (`passkey`, `password`, `gitlab`; default all). `LOGIN_METHODS=gitlab` leaves only "Sign in with GitLab": the sign-in page shows no username, password or passkey, the server refuses those routes, the settings hide passkeys and password, and the GitLab link cannot be removed. Without a configured GitLab sign-in, or with an unknown method, the server does not start instead of locking everyone out.

### Plugin API

- 1.1.0: blocks in notes (`ClientPlugin.blocks` with `PluginBlock`/`PluginBlockProps`), MCP tools (`ServerPlugin.mcpTools` with `PluginMcpTool`/`PluginToolCall`) and notifications (`ctx.notify` with `PluginNotification`). Additions only: plugins written for 1.0 keep working.
- 1.0.0: first version: `defineServerPlugin` (migrations, routes, public routes, note events, jobs, account export, context with database, encryption, notes through the sync, users, feature state, `PLUGIN_<ID>_*` variables) and `defineClientPlugin` (pages, navigation, commands, settings, `useKladde()` with API requests, notes on the device, navigation, toasts and the Werkbank components).

## [2.27.0] – 2026-11-27

- New: Cockpit source "Missing commits" (`gitlab.compare`): the commits of a branch or tag that another one lacks, e.g. whether everything in `10.100` reached `10.101`. Cherry-picked commits count as contained (by their "cherry picked from commit …" note or the same title) unless switched to "only the same commit"; merge commits are left out unless switched on.
- New: A count widget can show a state instead of the number: rules on the count (=, ≠, >, ≥, <, ≤) set the tile's text (`{{count}}` puts the number in), icon and background color, with a one-click "traffic light" (0 green, else red).
- New: Dashboards have an adjustable grid of 1 to 6 columns (default 2, in the dashboard settings); a widget's width is chosen in columns. Phones keep one column, tablets at most two.

## [2.26.0] – 2026-11-27

- New: Two more cockpit sources for GitLab: "Repositories" lists the projects of a group (with its subgroups unless switched off; archived ones hidden, shown or only those; search by name) or, without a group, the ones you are a member of, with path, group, description, visibility, default branch, topics, stars, forks, open issues and last activity. "Groups" lists the subgroups of a group (direct ones or all levels below) or your own groups, with path, parent group, description and visibility. Both work in dashboards, in ```` ```cockpit ```` blocks (`source: gitlab.projects` / `gitlab.groups`) and with notifications about new entries.
- New: `/cockpit` in the editor (with the development cockpit on) opens the cockpit's widget editor and puts the widget into the note as a ```` ```cockpit ```` block. A block's new settings button (top right of the widget) opens the same editor and writes the changes back; the ✎ button for the raw text moved to the widget's footer.
- Changed: The widget editor is wider and no longer shows the JSON definition. Instead it has "Copy as JSON", "Copy as Markdown" (the ```` ```cockpit ```` block for a note) and "From JSON", which takes over a pasted widget or block.

## [2.25.0] – 2026-11-27

- New: Development cockpit (opt-in under Settings → Features): the page "Cockpit" (`/cockpit`) in the navigation shows dashboards of live widgets that read GitLab and Jira with each user's own token (Settings → Features → Development cockpit → Settings: a GitLab personal access token for one of the configured instances, Jira Cloud with e-mail and API token or Jira Data Center with a personal access token; tokens are stored encrypted and never reach the browser). Sources: merge requests (by me, my reviews, assigned to me or all, per project or group, with state, drafts, labels and search), failed CI jobs across all repositories (the latest run per branch and job, filtered by job name, branch, period and group) and Jira issues in JQL. Every widget is plain configuration: filters, sort order, limit, view (list, table, count or board), fields, highlight rules and optional notifications: the server checks notifying widgets every 5 minutes and reports new hits in Kladde and as Web Push. Switching the feature on creates the dashboard "My day" (waiting for review, my reviews, failed CI jobs, my Jira issues, a watched module). Widgets and whole dashboards are copied as JSON for colleagues, without tokens; `{{var:name}}` placeholders are filled from each dashboard's variables. Dashboards are hidden notes `_dashboard-<uuid>.md` that sync like notes, also in groups as team dashboards; the data is only read live and kept in memory, so an open dashboard shows the last answer with its time while offline. In ordinary notes a ```` ```cockpit ```` block (JSON or a short YAML form) shows a widget and reads the note's properties as `{{this.key}}`.
- New: Break game (opt-in under Settings → Features): “Notebook flight” on the home page, a small 2D game in the Kladde look. The notebook flaps across dotted paper through the gaps between pencils above a ruler; space, the up arrow, Enter or a click or tap lifts it, every gap passed scores a point and it slowly gets faster. It follows the color scheme and the accent, pauses when you click elsewhere, scroll away or switch tabs, and keeps the best score on this device.

## [2.24.0] – 2026-11-26

- Docs: Guide to setting up an HTTPS certificate in front of Kladde (`docs/installation/HTTPS.md`, German `HTTPS.de.md`): Caddy, nginx with certbot, Traefik, and for home networks a DNS challenge, Tailscale or an own CA, with checks and common problems.
- New: Habit tracker (#134, opt-in under Settings → Features): the page "Habits" (`/habits`) sets up habits with a name, an emoji and a target (daily or n times a week), checks them off for today or the last seven days, and shows the current and longest streak, the rate of the last 30 days and a heatmap of 17 weeks. The habits live in a hidden note `_habits-<uuid>.md` of the own space; a check-in is a done task `- [x] … #habit/<id>` in that day's daily note, so the history stays plain Markdown. The home page shows today's habits to check off.
- New: Link preview (#130, opt-in under Settings → Features): hovering a `[[link]]` in the editor shows a card with the linked note's title and the beginning of its text; `[[Note#Heading]]` and `[[Note#^block]]` show that part, and a missing note says so. On touch screens a long press opens the card. Clicking the card opens the note.
- New: Semantic search in the app (#84): the search overlay shows "Similar matches" below the exact ones, notes about the same thing found by word stems, compounds, German/English concept groups and links, like the MCP tool `semantic_search`. The links tab of a note's side panel lists "Related notes" by the same index. With all notes on the device it runs there; in online mode the server answers (`GET /api/online/semantic`).
- New: Saved searches (#78): "Save search" in the search overlay (Ctrl/⌘+K) keeps the query under a name, and "Save view" on the task page keeps its filters and layout. Saved searches have their own section in the sidebar, with the number of matching notes, and open the overlay with their query or the task page with its filters; their menu (right click or ⋮) renames, moves and removes them. They are a synced setting, encrypted like the notes, so every device has them.
- New: Subtasks with progress and task dependencies (#75): tasks indented below a task are its subtasks, and the parent shows "2/5" in the editor, on the task page and in the Kanban board. `🆔 id` (or a block id `^id` at the end) names a task, `⛔ id` or `after:^id` (several: `⛔ a,b`) makes another one wait for it, also across notes; waiting tasks are marked, and "Next steps only" on the task page hides them. Query blocks know `waiting`, `subtasks` and `parent` for tasks, MCP `list_tasks` returns `parent_line`, `subtasks`, `id`, `waits_for` and `waiting`. Settings → Appearance → "Complete parent tasks" ticks off a parent when its last subtask is done (per device).
- New: Select several notes in the note list (#132): ⋮ → "Select notes", or Ctrl/⌘+click a note (Shift+click selects a range). A bar shows how many are selected and moves them to another folder, adds a tag, makes them favorites or deletes them (with undo). Escape or "Done" ends the selection; it works in the card, list and table views.
- New: Undo right after deleting (#131): deleting a note, an inbox note or a folder with its notes shows "… deleted · Undo" for a few seconds (longer while the pointer or the focus is on it). Undo brings the notes back at their old place, from the trash or, while offline, straight on the device.
- New: Find and replace inside a note (#129): Ctrl/⌘+F opens a find bar above the text with the number of matches, match case, whole words and regular expressions; Ctrl/⌘+Alt+F (Ctrl+H on Windows and Linux) opens it with replace and replace all. Enter and Shift+Enter (or F3, Ctrl/⌘+G) move between matches, Escape closes it. On phones it is in the toolbar and in the ⋮ menu ("Find and replace"), and the command palette has "Find in note" and "Replace in note". Read-only notes get find without replace.
- New: More due date words in tasks (#133): `due:übermorgen`, weekdays (`due:freitag`, `due:friday`, `due:fri`: the next one after today), `due:in-3-tagen`/`due:in-2-weeks`/`due:in-1-monat`, `due:nächste-woche`/`due:next-week` (Monday), `due:nächster-monat`/`due:next-month` (the 1st), `due:ende-woche`/`due:end-of-week` (Sunday) and `due:ende-monat`/`due:end-of-month`. Like `due:morgen` they become a date when the note is saved; the Apple Shortcuts task action accepts them too.
- Changed: Pinching no longer zooms the whole app on phones and tablets, so the top bar and the navigation stay in view. Settings → Editor → "Pinch to zoom" turns it back on for this device; the graph keeps its own pinch zoom.

## [2.18.0] – 2026-11-22

- New: Online mode for teams that are always online with very large vaults (`KLADDE_MODE=online`, experimental). Devices keep only a list of the notes and load a note's text when it opens, instead of a full offline copy: with 100,000 notes the first start takes 8 instead of 13 seconds and a restart 2 instead of 10. Renaming a note rewrites the links in every note on the server. Without a connection only notes opened before can be read; the local graph beside a note shows only opened notes so far.
- New: In online mode the server searches every note and finds the backlinks and unlinked mentions of a note, also of notes a device never opened. It keeps one index per group or account, shared by everybody who sees it. With 100,000 notes opening a note takes under 3 instead of 5.5 seconds.
- New: In online mode the task page, home and the navigation badge show the tasks of every note: the server sends them, and after the first time only what changed. Database tables (with `subfolders` also the rows below) and ticket projects (with their milestones) load their notes in full, so tables, boards, the backlog and "My tickets" see every row. With 100,000 notes and 200,000 tasks the task page shows after half a second. The catalog and the tasks travel compressed (20 MB become 2 MB).
- New: In online mode the graph shows every note and link: the server builds it (once per change, shared by everybody who sees the same notes) and the page shows a loading bar until it is there. Query blocks run on the server over every note; they show a loading bar on first sight and at most 2,000 rows (with a hint to narrow the query).
- Changed: Large graphs no longer freeze the page: above 1,500 notes the layout runs in the background behind a progress bar, and above 8,000 notes the notes are grouped by folder instead of simulated (with 100,000 notes 80 ms instead of over 30 seconds). Drawing is batched and skips what is out of view, and the graph is laid out again only when its notes or links change.
- Changed: Faster with very large vaults (measured with 100,000 notes): the first sync, the start until the folder tree is filled, search, the task page and the graph take a third less time. Notes above 20,000 were parsed again on every change.
- Changed: Task lists sort and group faster with very many tasks, and the folder tree, the feature settings and the folder counts are no longer recomputed for every folder and every render, in both modes.

## [2.15.0] – 2026-11-21

- New: Ticket workflows. The project settings open in a dialog that uses the whole window, with sections for General, Statuses, Transitions, Automations and Git integration; nothing has to be written in the frontmatter any more.
- New: Statuses are edited as a list: rename (the project's tickets move along), reorder, add and remove them and set their category (open, in progress, done).
- New: Transitions. "Enforce the order" decides which status may follow which, set in a matrix or with the presets "Forward only" and "Step by step, forward and back". The board only takes drops on allowed columns, the status menus only offer allowed statuses, `ticket_update` (MCP) names the allowed ones, and the server undoes a change that is not allowed (also one typed into the note) while keeping the rest of the text.
- New: Automations ("when … then …"): when a ticket is created, its status changes (from/to), all its sub-tasks are done, or a merge request is opened, merged or closed, Kladde sets the status, priority or assignee (also the person who caused it), adds or removes a label or appends a comment with placeholders such as `{{mr.url}}`. Rules can be limited to statuses and labels, switched off, reordered and started from templates ("Merge sets the status", "Assign on start", …); a rule may skip the transitions. They run on the server, so they also apply to changes from other devices and AI assistants.
- New: GitLab and GitHub webhooks per project (`/api/hooks/<id>`, secret token or HMAC signature). Merge requests and pull requests that name a ticket (`KLD-12` in the title, branch or description) run the merge request automations, e.g. "merged → Implemented". The settings show the address and the secret once, setup steps for both providers and the result of the last delivery. Not available in the desktop app without a server.
- New: Ticket types. Every ticket is an Epic, Feature, Task, Bug or Subtask (frontmatter `kind`, Task by default) and can belong to a parent ticket (`parent`): features below an epic, tasks and bugs below a feature or epic, subtasks below a task, bug or feature. A ticket shows its path from the top, its child tickets with their progress over all levels and buttons to create a child of the fitting type; cards and the backlog show the type's icon, the parent and the child progress, and the project can be filtered by type. `ticket_create`, `ticket_update` and `list_tickets` (MCP) know `kind` and `parent` and check the hierarchy.
- Changed: Linking documentation to a ticket is a search: typing finds notes by title, folder and text (arrow keys and Enter, or a tap), and Enter without a hit still links the typed title. The same search is in the "New ticket" dialog, where several notes can be linked.
- Changed: Tickets and milestones hide the frontmatter row above the text, because the panel above already shows their fields; the code view and placing the cursor at the very top still show the raw frontmatter.
