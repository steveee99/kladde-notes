# Guidelines for AI Agents Working on Kladde

## Project Overview
Self-hosted, offline-first Markdown notes app (PWA) with npm workspaces, a hardened Docker image, invites, optional GitLab sign-in and a release script.

## Key Rules & Contracts
1. **Encryption at rest:** never store note paths/contents or attachments unencrypted in the database or `data/files`; use `DataCipher` with the record id as AAD.
2. **Spaces:** every query on notes must check ownership, a share or a group membership (`NoteStore.accessOf`). Only owners (for group notes: the group's owners and editors) rename, move or delete.
3. **Sync:** every accepted change takes the next global `seq`; clients pull `seq > cursor`. Conflicts never lose text: the client three-way merges against `LocalNote.base` (`merge3` in `shared/merge.ts`); only overlapping word edits fall back to "server wins, local copy is kept". Presence (who has a note open) lives in memory in `server/Presence.ts` and reaches clients as the SSE event `presence`; cursors (`POST /presence/cursor`, SSE `cursor`) carry the text before them so `resolveCursor` finds the spot in a slightly different text (`client/editor/remoteCursors.ts`).
4. **Theming:** the Werkbank design (`docs/DESIGN.md`). Colors only through the tokens in `client/src/index.css` (`--bg`, `--panel`, `--bar`, `--raised`, `--line`, `--line2`, `--strong`, `--text`, `--body`, `--soft`, `--muted`, `--faint`, `--edge`, the accent `--acc`/`--acc-hi`/`--acc-bg`/`--acc-line`/`--on-acc` and the states `--amber`, `--red`, `--violet`, `--green` with their `-bg`); Tailwind classes use the same names (`bg-panel`, `text-muted`, `border-line`, `bg-acc`). The Material 3 role names (`--surface-container-high`, `--on-surface-variant`, `--primary`, …) are kept as aliases onto these tokens for older views; new code uses the Werkbank names. Use the type scale (`text-title-m`, `text-body-m`, `text-caption`, …), the radii (`rounded` 4px pills, `rounded-md` 6px controls, `rounded-lg` 8px cards) and the components in `@layer components` (`.btn-primary`, `.btn-tonal`, `.btn-outlined`, `.btn-text`, `.btn-icon`, `.input`, `.card`, `.chip`, `.segmented`, `.kbd`, `.pill`, `views/Switch.tsx`); selected rows use `bg-line`, selected chips/segments `bg-acc-bg text-acc-hi`; lines instead of shadows (shadows only on floating layers). Fonts: Newsreader (serif with optical sizes) for titles and headings (`.font-display`, `.panel-title`, `.note-title`, the editor's h1–h3), Inter for the interface and JetBrains Mono for numbers and dates, all self-hosted through `@fontsource-variable`; captions in sentence case, never letter-spaced uppercase. Notebook marks (`.paper-dots`, `.paper-grid`, `.empty-sheet`, `.note-sheet`, `views/AppLogo.tsx`) are used sparingly, and a page has at most one filled accent button. Icons come from `lib/icons.tsx`, generated from Material Symbols Rounded weight 300 by `packages/client/scripts/gen-icons.mjs` (add new icons to its map, then `npm run icons --workspace=packages/client`). The shell is `views/WerkbankShell.tsx` (`data-theme="werkbank"`): on the desktop a top bar with the search field, the icon rail, the collapsible folder panel (`Sidebar` with `panel`; open/collapsed per device in `lib/sidebarMode.ts`, `Ctrl/⌘+\`), tabs of open notes (`views/NoteTabs.tsx`, `lib/tabs.ts`), the content, the right inspector and a status bar; on phones a top bar, the bottom navigation bar and the drawer. It switches with the `nav:` screen from `tailwind.config.js` (768px with a mouse/trackpad, touch screens only in landscape from 1024px), not with `md:` (because `nav` is a raw media query Tailwind generates no `max-*` variants: use `phone:` (below 640px) instead; extra bottom bar destinations use `tablet:`). Settings have their own navigation (`views/SettingsNav.tsx`; routes in `lib/settingsRoutes.ts`), shown in the side panel on settings routes and as the `/settings` list on phones; new settings pages get an entry there. The command palette is `views/SearchDialog.tsx` (Ctrl/⌘+K): new commands go into `buildCommands` in `views/commands.tsx`. Pages use `PageHeader`/`PageBody`/`Panel` from `views/PageHeader.tsx`. Color schemes dark (default), light and Catppuccin Mocha, selected by `data-scheme` on `<html>` (Mocha is `data-scheme="dark"` plus `data-palette="mocha"`), set by `lib/theme.ts` and the inline script in `index.html` from the per-device choice `kladde_color_scheme` (`dark`, `mocha`, `light` or `system`); the light values live in `[data-theme='werkbank'][data-scheme='light']`, Mocha's in `[data-palette='mocha']` (with its own accent values); syntax colors of code blocks are the `--syn-*` tokens, switched per device by `data-code-theme` (`lib/codeTheme.ts`: kladde, catppuccin, github, one, each with a dark and light set); Tailwind `dark:` maps to `[data-scheme="dark"]`. The accent belongs to the account (`Me.accent`, presets in `shared/accent.ts`, `PUT /api/me/accent`, column `users.accent`): `lib/accent.ts` sets `data-accent` on `<html>` and caches it for the inline script; every preset has a dark and a light value set in `index.css` and must reach WCAG AA on the surfaces it is used on.
5. **Untrusted note content:** notes come from other users (shares, public links) and AI assistants, so every URL from Markdown goes through `safeUrl` (`shared/util.ts`) before it reaches `href`/`src`; never build HTML from note text without escaping. The server sends a strict CSP (`server/security/csp.ts`): no inline scripts besides the hashed theme script in `index.html`, no CDNs.
6. **Schema:** add numbered migrations in `server/src/db.ts`, never edit a released one.
7. **Links:** resolve `[[links]]` only through `LinkIndex` (title, frontmatter `id`, Zettel id prefix); renaming a note must keep rewriting links (`vault.update` → `relink`).
8. **Commands:** `npm run build`, `npm run test` (`npm run test:coverage` for v8 coverage, reports in each package's `coverage/`; client tests in `packages/client/tests/` run in Node, files that need a DOM start with `// @vitest-environment jsdom`, and `tests/support/syncServer.ts` syncs devices with their own fake IndexedDB against the real server in-process), `npm run dev` (`npm run dev:online` with `KLADDE_MODE=online`; `npm run seed -- --notes <n> [--group <name> --members <n>]` fills the dev database with the large vault of `e2e/fixtures/largeVault.mjs`); browser tests `npm run test:e2e` (Playwright, `e2e/`: own server with a fresh database and the accounts anna/ben/cara, phone/tablet/desktop projects, axe checks in `e2e/a11y.spec.ts`, findings in `docs/ACCESSIBILITY.md`); benchmarks `npm run bench` and `npm run bench:e2e` on the large vault of `e2e/fixtures/largeVault.mjs` (numbers in `docs/PERFORMANCE.md`).
9. **Versioning & Changelog:** one SemVer version for the monorepo; user-facing changes go (English) under `## [Unreleased]` in `CHANGELOG.md`; release with `npm run release -- patch|minor|major`.
10. **Large vaults (#64):** work over all notes must not redo per-note parsing after every change: use `NoteMemo`/`TaskCache` (`shared/noteMemo.ts`, `shared/tasks.ts`) or build a `LinkIndex` from the previous one; sort with `compareText` (`client/lib/i18n.ts`), never `localeCompare` with a locale argument; write many notes to IndexedDB in one transaction with one `emit`. Graphs above 1,500 notes are laid out ahead in a Web Worker behind a progress bar (`client/lib/graphLayout.ts`), above `FORCE_MAX` by folder instead of by forces.
11. **Dialogs:** sheets and dialogs get `role="dialog"`, a name and `useModal` (`client/lib/modal.ts`: focus in, Tab trapped, Escape, focus back).
12. **Plugins:** plugins use only `@kladde/plugin-api`; anything it exports is a contract. Changing it means a SemVer bump of the plugin API (additions minor, removals/changes major, deprecate first, CHANGELOG section "Plugin API"), and CI's build with the example plugin must pass. Never let plugin code reach Kladde's internals (no new exports of stores, no raw table names).

## Git
The project works on **`main`** (GitHub: `steveee99/kladde-notes`). Changes from outside come as pull requests.

Rules for agents:
1. Finished work must pass `npm run lint`, `npm run build` and `npm run test`. Commit or push only when the user asks for it.
2. Commit messages in English, Conventional Commits (`feat:`, `fix:`, `perf:`, `docs:`, `chore:`, `ci:`; `!` or a `BREAKING CHANGE:` footer for breaking changes), ending with the attribution lines the session asks for.
3. Never rewrite history on `main` (no amend of pushed commits, no reset, no force).
4. Changelog entries (English) go under `## [Unreleased]` in `CHANGELOG.md`.
5. Run `git pull --rebase` before committing.
6. Never put private infrastructure details (hostnames, IPs, registries, SSH targets, e-mail addresses) into this repository.

### CI and releases
`.github/workflows/ci.yml` runs lint, build and tests on GitHub-hosted runners for every push to `main` and every pull request. `.github/workflows/pages.yml` publishes the browser-only demo (`npm run build:demo`, `client/src/demo/demoApi.ts` answers `/api` in the browser; routes go through `lib/router.ts`, which knows the base path) on GitHub Pages; there is no other deploy pipeline and no self-hosted runner. Versions are bumped with `npm run release -- patch|minor|major` (see `scripts/release.mjs`), then committed and tagged by hand.
