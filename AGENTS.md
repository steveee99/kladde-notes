# Guidelines for AI Agents Working on Kladde

## Project Overview
Self-hosted, offline-first Markdown notes app (PWA) with npm workspaces, a hardened Docker image, invites, optional GitLab sign-in and a release script.

## Monorepo Architecture
- `packages/shared`: Pure logic without browser or node dependencies: sync contracts (`types.ts`), Markdown metadata/frontmatter (`markdown.ts`), task parsing/recurrence (`tasks.ts`), the query language (`query.ts`), PARA roles and Zettel ids (`para.ts`), link resolution/backlinks/mentions/graph (`links.ts`), templates and the weekly review, PDF notes (`pdfNote.ts`: `type: pdf` frontmatter plus a PDF embed; `NoteView` shows them as a full-size viewer), release versioning (`release.ts`: SemVer bumps and the `{{version}}`/```` ```versions ````/`{{#versions}}` placeholders, filled when rendering and exporting), groups (`groups.ts`: roles, the last-owner rule, where moved notes land), folders as databases (`database.ts`, #76: a `_database.md` note with `type: database` holds typed properties and views in its frontmatter; rows are the notes directly in the folder, values stay plain frontmatter written by `setCell`; UI in `client/views/DatabaseView.tsx`, new empty notes in such a folder are prefilled in `vault.create`), the AI memory (`memory.ts`, #94: OKF-compatible metadata, trust level, validation, stamping, index/log upkeep via `memoryUpkeep`, rules for agents, OKF bundle export/import; nested frontmatter through the YAML subset in `yaml.ts`, `setFrontmatterValues` keeps other keys as written).
- `packages/server`: Express + `node:sqlite`. Passkey auth (`auth.ts`, SimpleWebAuthn), GitLab OAuth sign-in (`gitlabAuth.ts`, identities in `external_logins`), `NoteStore` (encrypted notes, global seq cursor, shares, public links, trash: deleted notes keep path/content encrypted in `trash` until restored or purged; opt-in release versioning (#53): `note_versioning` + immutable `note_releases` (a DB trigger refuses updates), read-only recipients and public links get the latest release, exports go through `published()`; `trash.ts` purges after `TRASH_RETENTION_DAYS` and drops unused attachments), `GroupStore` (groups, #58: a group is a `users` row with `is_group = 1` that can never sign in, so it owns notes, trash and attachments like a user; `group_members` gives each member a role `owner`/`editor`/`reader`; the last owner can neither leave nor lose the role; `UserStore` hides group rows; group notes reach members through `NoteStore.pull`, `NoteStore.moveToGroup` moves own notes in and ends their shares, `NoteStore.deleteGroup` removes everything), `FileStore` (encrypted attachments), `ExportMirror` (plain Markdown to `EXPORT_DIR`), admin area (`admin/adminRouter.ts`; backups in `backup/BackupService.ts`, #65: a folder per backup with a `VACUUM INTO` copy and hard links to the encrypted `files/`/`avatars/`, never the key; restores leave `restore-pending.json`, restart and are applied by `applyPendingRestore` before the database opens; the schedule lives in `server_settings` via `ServerSettings`), `mcp/` (MCP endpoint `/mcp` with OAuth 2.1 + personal tokens in `McpTokenStore`; with the AI memory on (feature `memory`), writes into its folder are checked, stamped with the connection name and followed by index/log upkeep, `memory_save`/`memory_check` work on it and `protocol.ts` adds its `Rule` notes to the instructions, resources and prompts; tools in `mcp/tools.ts` see the token owner's own notes via `NoteStore.ownedNotes` and their groups' notes via `NoteStore.groupNotes` (shown below the group name, readers cannot write), and write through `NoteStore.push`), `import/` (bearer-only `/api/import` with import tokens in `ImportTokenStore` (at most 5 per user, each with an expiry date), separate from MCP tokens; lists own note paths, uploads attachments and creates only new notes through `NoteStore.push`). `importCli.ts` (`npm run import`) is the local import CLI that talks to that API (`http://` only with `--allow-insecure`); it shares the scan and link rewriting in `importScan.ts` with the server CLI import and opens no database.
- `packages/client`: React 18 + Vite + Tailwind + CodeMirror 6. `data/vault.ts` is the offline store (IndexedDB) and sync engine; `editor/livePreview.ts` builds all decorations in one StateField (block widgets need it).

## Key Rules & Contracts
1. **Encryption at rest:** never store note paths/contents or attachments unencrypted in the database or `data/files`; use `DataCipher` with the record id as AAD.
2. **Spaces:** every query on notes must check ownership, a share or a group membership (`NoteStore.accessOf`). Only owners (for group notes: the group's owners and editors) rename, move or delete.
3. **Sync:** every accepted change takes the next global `seq`; clients pull `seq > cursor`. Conflicts never lose text: the client three-way merges against `LocalNote.base` (`merge3` in `shared/merge.ts`); only overlapping word edits fall back to "server wins, local copy is kept". Presence (who has a note open) lives in memory in `server/Presence.ts` and reaches clients as the SSE event `presence`; cursors (`POST /presence/cursor`, SSE `cursor`) carry the text before them so `resolveCursor` finds the spot in a slightly different text (`client/editor/remoteCursors.ts`).
4. **Theming:** colors only through the Material 3 color roles in `client/src/index.css` (CSS variables named after the roles, e.g. `--surface-container-high`, `--on-secondary-container`; Tailwind classes use the same names: `bg-surface-container`, `text-on-surface-variant`). The values come from `@material/material-color-utilities` (scheme Tonal Spot, source color #0B57D0); `ok`/`warn` are harmonized custom colors. Use the M3 type scale (`text-title-m`, `text-body-l`, …), the shape scale (`--shape-*`, Tailwind `rounded-*` maps onto it) and the components in `@layer components` (`.btn-primary`, `.btn-tonal`, `.btn-outlined`, `.btn-text`, `.btn-icon`, `.input`, `.card`, `.chip`, `.segmented`, `views/Switch.tsx`); selected states use `secondary-container`. Icons come from `lib/icons.tsx`, generated from Material Symbols Rounded by `packages/client/scripts/gen-icons.mjs` (add new icons to its map, then `npm run icons --workspace=packages/client`). There is one Material 3 design (`data-theme="material"`, with its own layout in `views/MaterialShell.tsx`, chosen in `Shell` via `useResolvedTheme`); it switches between the mobile layout (top bar, bottom navigation bar, drawer) and the desktop layout (rail or sidebar) with the `nav:` screen from `tailwind.config.js` (768px with a mouse/trackpad, touch screens only in landscape from 1024px), not with `md:` (because `nav` is a raw media query Tailwind generates no `max-*` variants: use `phone:` (below 640px) instead; extra bottom bar destinations use `tablet:`) with two color schemes: dark (default) and light. The scheme is selected by `data-scheme` (`dark`/`light`) on `<html>`, set by `lib/theme.ts` and the inline script in `index.html` from the per-device choice `kladde_color_scheme` (`dark`, `light` or `system`, which follows the OS). The light values live in `[data-theme='material'][data-scheme='light']`; the choice `darker` keeps `data-scheme="dark"` and adds `data-tone="darker"` (neutral grey surfaces in `[data-scheme='dark'][data-tone='darker']`); Tailwind `dark:` maps to `[data-scheme="dark"]`.
5. **Untrusted note content:** notes come from other users (shares, public links) and AI assistants, so every URL from Markdown goes through `safeUrl` (`shared/util.ts`) before it reaches `href`/`src`; never build HTML from note text without escaping. The server sends a strict CSP (`server/security/csp.ts`): no inline scripts besides the hashed theme script in `index.html`, no CDNs.
6. **Schema:** add numbered migrations in `server/src/db.ts`, never edit a released one.
7. **Links:** resolve `[[links]]` only through `LinkIndex` (title, frontmatter `id`, Zettel id prefix); renaming a note must keep rewriting links (`vault.update` → `relink`).
8. **Commands:** `npm run build`, `npm run test`, `npm run dev`; browser tests `npm run test:e2e` (Playwright, `e2e/`: own server with a fresh database and the accounts anna/ben/cara, phone/tablet/desktop projects, axe checks in `e2e/a11y.spec.ts`, findings in `docs/ACCESSIBILITY.md`); benchmarks `npm run bench` and `npm run bench:e2e` on the large vault of `e2e/fixtures/largeVault.mjs` (numbers in `docs/PERFORMANCE.md`).
9. **Versioning & Changelog:** one SemVer version for the monorepo; user-facing changes go (English) under `## [Unreleased]` in `CHANGELOG.md`; release with `npm run release -- patch|minor|major`.
10. **Large vaults (#64):** work over all notes must not redo per-note parsing after every change: use `NoteMemo`/`TaskCache` (`shared/noteMemo.ts`, `shared/tasks.ts`) or build a `LinkIndex` from the previous one; sort with `compareText` (`client/lib/i18n.ts`), never `localeCompare` with a locale argument; write many notes to IndexedDB in one transaction with one `emit`.
11. **Dialogs:** sheets and dialogs get `role="dialog"`, a name and `useModal` (`client/lib/modal.ts`: focus in, Tab trapped, Escape, focus back).

## Git
The project works on **`main`** (GitHub: `steveee99/kladde-notes`). Changes from outside come as pull requests.

Rules for agents:
1. Finished work must pass `npm run lint`, `npm run build` and `npm run test`. Commit or push only when the user asks for it.
2. Commit messages in English, Conventional Commits (`feat:`, `fix:`, `perf:`, `docs:`, `chore:`, `ci:`; `!` or a `BREAKING CHANGE:` footer for breaking changes), ending with the attribution lines the session asks for.
3. Never rewrite history on `main` (no amend of pushed commits, no reset, no force).
4. Changelog entries (English) go under `## [Unreleased]` in `CHANGELOG.md`.
5. Run `git pull --rebase` before committing.
6. Never put private infrastructure details (hostnames, IPs, registries, SSH targets, e-mail addresses) into this repository.

### CI and releases
`.github/workflows/ci.yml` runs lint, build and tests on GitHub-hosted runners for every push to `main` and every pull request. `.github/workflows/pages.yml` publishes the browser-only demo (`npm run build:demo`, `client/src/demo/demoApi.ts` answers `/api` in the browser; routes go through `lib/router.ts`, which knows the base path) on GitHub Pages; there is no other deploy pipeline and no self-hosted runner. Versions are bumped with `npm run release -- patch|minor|major` (see `scripts/release.mjs`), then committed and tagged by hand.
